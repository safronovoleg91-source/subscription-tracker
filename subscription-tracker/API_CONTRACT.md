# Контракт API между фронтендом и бэкендом

Фронтенд (Олег) пока написан «на глаз», без готового API. Ниже то, что он **ожидает** от сервера.
Если у бэкенда (Кирилл) получится иначе, править нужно только в `static/js/core.js`:

| Что поменялось | Где править в `core.js` |
|---|---|
| адреса запросов | `CONFIG.endpoints` |
| названия полей в ответе | `normalize()` |
| названия полей в запросе | `toPayload()` |

Если сервер не отвечает (нет сети, 404/405/501 вместо JSON), фронтенд включает **демо-режим**
с тестовыми данными и жёлтой плашкой на странице. Когда API заработает, демо-режим отключится сам;
при желании его можно выключить совсем: `CONFIG.demoFallback = false`.

Все запросы идут с cookie-сессией (`credentials: 'same-origin'`), тело — JSON.
Ошибки: статус 4xx/5xx и JSON `{"error": "понятный текст"}` — текст показывается пользователю.
Статус `401` — фронтенд перенаправляет на `/login`.

## Авторизация (уже была в проекте)

| Метод | Адрес | Тело | Ответ |
|---|---|---|---|
| POST | `/api/register` | `{username, password}` | `201` / `{error}` |
| POST | `/api/login` | `{username, password}` | `200` / `{error}` |
| POST | `/api/logout` | — | `200` |
| GET | `/api/me` | — | `{username, created_at}` |
| POST | `/api/change-password` | `{current_password, new_password}` | `200` / `{error}` |

## Подписки

Подписка в ответе сервера:

```json
{
  "id": 1,
  "name": "Netflix",
  "category": "Развлечения",
  "cost": 799,
  "billing_date": "2026-10-15",
  "usage_count": 12,
  "last_used_at": "2026-10-17T18:30:00",
  "started_at": "2025-10-15"
}
```

| Поле | Смысл |
|---|---|
| `cost` | цена в рублях за месяц |
| `billing_date` | дата списания, `YYYY-MM-DD` |
| `usage_count` | сколько раз пользовались **в текущем месяце** |
| `last_used_at` | когда пользовались последний раз (`null`, если ни разу) |
| `started_at` | с какого дня подписка (нужно для «потрачено за всё время») |

Категории: Развлечения, Музыка, Здоровье, Учёба, Другое.

| Метод | Адрес | Тело | Ответ |
|---|---|---|---|
| GET | `/api/subscriptions` | — | массив подписок (подходит и `{"subscriptions": [...]}`) |
| POST | `/api/subscriptions` | `{name, category, cost, billing_date}` | созданная подписка |
| PUT | `/api/subscriptions/<id>` | `{name, category, cost, billing_date}` | обновлённая подписка |
| DELETE | `/api/subscriptions/<id>` | — | `200` или `204` |
| POST | `/api/subscriptions/<id>/usage` | `{}` | обновлённая подписка |

Все подписки должны быть **только текущего пользователя**.

### Что нужно от базы данных

Для «использования» нужна таблица логов, например `usage_log(id, subscription_id, used_at)`.
Тогда:

- `usage_count` = число записей за текущий календарный месяц;
- `last_used_at` = максимальный `used_at`;
- `POST /api/subscriptions/<id>/usage` просто добавляет запись с текущим временем.

## Что считает фронтенд сам

Сервер этого считать не обязан: фронтенд берёт список подписок и считает суммы в месяц и в год,
траты по категориям, «потрачено за всё время» (по `started_at`), цену одного использования
(`cost / usage_count`), статус подписки (нет использований — «не используется», 1–2 — «редко»,
больше — «активно») и возможную экономию (подписки, которые не «активны»).
Пороги лежат в `CONFIG` в `core.js`.
